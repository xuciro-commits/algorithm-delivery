## 2. 设计总则

以下 10 条是本设计的硬约束，M1 实现与验收均以此为准：

1. **引擎零改动** —— M1 所有代码位于 `lab/src/modules/mapf/`、`lab/src/components/grid-map/` 与 `lab/scripts/`；`mapf/rust/**` 与 `mapf/contracts/**` 一行不改。
2. **契约即场景模型** —— 编辑器操作的"场景文档"就是 `MapfProblem/1.0` 的内存对象（`map.cells` + `robots[].start/goal` + `time_model` + `objective` + `solver` + `tags`），**不另建私有场景格式**；相机、工具、图层开关等纯 UI 状态与场景文档严格分离（§5.1）。
3. **真实计算** —— 地图上出现的任何路径、机器人位置、冲突、指标，只能来自 WASM 引擎输出（`MapfSolution` / verify 报告）；前端不做任何求解、不伪造动画。
4. **离散时间诚实呈现** —— 回放是离散时间步的逐格重演：机器人在格心之间按步跳变，**不做步内插值、不做连续速度曲线**，避免暗示连续运动控制（SRS §5.4）。
5. **渲染三层解耦** —— 求解（Worker）与渲染互不阻塞；渲染（Canvas + rAF）与 React 状态更新解耦；React 仅在语义状态变化时更新（§11）。
6. **JSON 降级为高级模式** —— 主流程零 JSON；JSON 编辑器保留在"高级"抽屉中，双向同步（§5.6）。
7. **复用而不重建** —— 沿用 Lab 外壳、hash 路由、样式 token、CI/Pages/Release；仅最小抽取无算法语义的栅格地图原语（§12），**不创建新 UI 框架**。
8. **验证器独立呈现** —— 冲突 = 独立验证器的 violations（带 `at_time/cell`，可在地图定位）；求解器搜索过程中的候选冲突只以"搜索统计"折叠呈现，**绝不渲染为最终方案的碰撞**（SRS §5.5）。
9. **能力边界透明** —— wasm-light 限额、`UNSUPPORTED`、`INVALID_INPUT`、动态事件被拒等原因逐条如实展示；做不到的操作解释原因，不伪造成功。
10. **可测试性** —— 场景文档操作、预检、回放时钟、事件构造全部是纯 TS 模块，Node 可直接测（延续 `test:render / test:core` 的无浏览器测试模式）。

### 3.2 三种工作模式（左栏内容组切换，地图永不在场外）

| 模式 | 进入条件 | 左栏强调 | 地图状态 |
|---|---|---|---|
| **场景（编辑）** | 默认；或点"编辑场景" | 编辑工具组展开，求解控制可用 | 起终点/障碍可编辑；若有旧解，旧路径以极淡虚线保留作参照 |
| **回放（结果）** | 求解成功自动进入 | 工具收起，回放信息（状态徽章、目标值） | 完整路径图层 + 回放机器人；编辑需显式切回（防误触改动作废对比基准） |
| **对比（历史）** | 点开"运行历史" | 运行列表（按问题指纹分组） | A/B 切换渲染两次运行的路径（§10） |

动态事件是回放模式内的子模式（§9），通过工具浮条上的"⚡ 注入事件"进入。

### 3.3 首屏行为（V01）

1. 模块打开即渲染地图工作区：默认载入**上次会话场景**，无历史则载入内置"交叉示例"（即 m02，3×3 双车对角）——最小、最快建立"这是地图"的认知；
2. 未求解时：障碍、起点、终点、机器人初始位置全部可见；中央浮动引导"设置好起终点后点击【求解】"；
3. 引擎并行装载（Worker 握手 8s 超时已存在）：装载中可自由缩放/平移/编辑场景，仅【求解】按钮禁用并显示"引擎装载中…"；装载失败给出重试按钮（现有语义保留）。

## 4. 地图工作区与交互模型

### 4.1 分层 Canvas 架构

一个 `MapStage` 容器内叠 4 块 Canvas（同尺寸、`position:absolute`），由非 React 的渲染器（`MapRenderer` 类）统一驱动：

| 层 | 内容 | 重绘时机 |
|---|---|---|
| L0 基底（离屏缓存） | 背景、网格线、障碍、**静态**地图文本（行列号） | 仅当 场景地图 / 视口 / 主题 变化 |
| L1 轨迹 | 规划路径（未来段虚线 / 已执行段实线）、冻结前缀（锁纹）、旧方案参照线 | 选择 / 图层开关 / 回放步变化 |
| L2 实体 | 机器人当前位置与状态符号（等待/移动/到达/驻留）、起终点标记 | 回放步变化（每帧最多一次） |
| L3 交互 | 悬停格高亮、编辑预览（画刷范围、非法红框）、事件标记、冲突定位脉冲 | 鼠标/指针事件（节流至 rAF） |

只有 L3 跟随指针事件高频重绘；L0 走离屏缓存位块传输；L1/L2 在回放时每步一次。React 不持有任何 canvas 绘制逻辑（§11.1）。

### 4.2 视口模型（缩放 / 平移 / 适配）

- 单一 `Viewport { scale, tx, ty }`，`cell→px` 与 `px→cell` 换算只经这一处；devicePixelRatio 上限 2（防 4K 高 DPI 下离屏超限）。
- **滚轮缩放**：以光标为锚点（光标下的格保持在光标下），缩放范围 = 适配倍率的 0.3×–8×；触控板双指 = 缩放，双指拖动 = 平移。
- **平移**：空格按住拖动 / 中键拖动 / "抓手"工具；惯性不做（非必要复杂度）。
- **适配窗口（fit）**：一键回到全图含 1 格边距；`F` 键快捷；切换场景后自动 fit 一次。
- **网格显隐**：`G` 键与图层开关同步。
- **视口裁剪（culling）**：L0 缓存整图，但 L1/L2/L3 只绘制可视矩形内的格与路径段——161×63 仓库图在 8× 放大时仍只画屏幕内的实体。

### 4.3 细节层级（LOD）——密集场景不糊屏

以"当前 1 格 = 多少屏幕像素"为唯一驱动量：

| cell px | 网格线 | 机器人序号 | 路径线 | 起终点 | 备注 |
|---|---|---|---|---|---|
| ≥ 22 | 显示 | 圆内数字 | 3px 圆角折线 | 描边框 + 菱形 + 坐标微标 | 全细节 |
| 14–21 | 显示 | 数字 | 2.5px | 描边框 + 菱形 | 去坐标微标 |
| 8–13 | 每 2 格一条 | 隐藏（悬停显示 tooltip） | 2px | 简化为色块角标 | 悬停 tooltip 补读数 |
| < 8 | 隐藏 | 隐藏 | 1.5px、同色多车合并透明度叠加 | 色块角标 | 密集大图浏览态 |

选中机器人在任何 LOD 下保持全细节 + 强调描边（用户永远看得到自己在跟谁）。

### 4.4 图层控制（右栏，9 组开关 + 全显/全隐）

障碍 · 网格 · 起点 · 终点 · 规划路径（未来段） · 已执行轨迹 · 机器人当前位置 · 冲突标记（验证违规时可用） · 事件标记（动态模式下可用）。默认全开；图层状态是纯 UI 状态，不入场景文档。

### 4.5 拾取与悬停

- 悬停：格高亮 + 左下角读数 `(x, y) · 可通行/障碍` + 该格当前时刻占用者 id；
- 点击拾取优先级：**机器人当前位置 > 终点标记 > 起点标记 > 空白格**（交给当前工具消费：选择工具选中机器人，画障碍工具落格，……）；
- 拖拽框选（选择工具下）批量选中机器人 → 列表与时间轴同步多选高亮（路径叠加显示）。

## 5. 场景编辑器

### 5.1 场景文档 = MapfProblem（无私有模型）

```ts
/** 场景文档：就是 mapf-problem/1.0 的内存表示（严格白名单字段）。 */
type SceneDoc = {
  schema_version: 'mapf-problem/1.0';
  id: string;                       // 自动生成 mapf-scene-<n>，可改
  map: { cells: string[] };         // 每行一个字符串，'.' 可通行，'#' 障碍
  time_model: { timestep: 'discrete'; horizon: number | 'auto' };
  objective: { kind: 'soc' | 'makespan'; direction: 'min' };
  robots: Array<{ id: string; start: [number, number]; goal: [number, number] }>;
  solver: { planner: 'auto' | 'ecbs' | 'cbs' | 'pp'; time_limit_ms: number;
            seed: number; suboptimality_factor: number };
  tags?: { name: string; description: string };
};
```

- UI 状态（当前工具、相机、图层、选择、回放位置）**独立**存放，永不混入 `SceneDoc`；
- 序列化 = 严格按契约白名单逐字段生成 JSON（多一字段都不输出），可直接 `mapf solve` / 被现有 check_contracts 校验；
- `map.blocked` 表达不使用（编辑器统一产出 `cells`，与 14 个 mock 一致，diff 友好）。

### 5.3 编辑期合法性预检（即时、非阻断、镜像引擎错误码）

预检只做**结构层**（引擎在解析期就会拒绝的东西），用于编辑即时反馈；**解的合法性永远只由引擎与独立验证器裁决**（与 Lab"前端不重算约束"原则一致，SRS §5.2 只要求"编辑器即时合法性检查"）：

| 预检项 | 对应引擎错误码（呈现时一并显示） | UI 行为 |
|---|---|---|
| 起点/终点落在障碍格 | `E-ROBOT-START-BLOCKED` / `E-ROBOT-GOAL-BLOCKED` | 该格红框 + 问题清单项 |
| 重复起点 | `E-ROBOT-DUP-START` | 两车同时闪烁 + 清单项，【求解】禁用 |
| 重复终点 | `E-ROBOT-DUP-GOAL` | 同上 |
| 起点 = 终点 | `E-ROBOT-START-EQ-GOAL` | 清单项 + 解释文案（本期契约拒绝退化输入） |
| 终点未设置（新加的车） | —（本地必填） | 机器人红色未完成态，【求解】禁用 |
| 越界坐标 | `E-ROBOT-COORD-RANGE` | 拖拽/输入时夹紧到界内 |
| 规模超 wasm-light 限额 | `E-CAP-LIMIT-AGENTS` / `-MAP` / `-HORIZON` / `-BUDGET` | 限额来自 `mapf_capabilities` 握手，不硬编码 |
| 地图无可通行格 | `E-MAP-MAP-EMPTY` | 清单项 |

呈现：右栏顶部"问题清单"（可折叠），每项可点击定位；【求解】按钮在有 error 级问题时禁用并显示首要原因；引擎返回的 `errors[]` 原文照登（引擎永远是最终裁决者）。

## 6. 机器人选择与联动

### 6.1 单一选择状态

`selection: { robotIds: string[]; primary: string | null }`（框选支持多选，详情面板只显示 primary，其余仅叠加路径）。

三处订阅同一状态：

1. **地图**：primary 机器人全细节强调（描边 + 名称标牌）；非选中机器人与路径统一降至 20% 透明度（"专注模式"自动生效）；多选时各自保持可分辨；
2. **右栏列表**：行高亮 + 滚动跟随（`scrollIntoView` 仅当由地图/时间轴触发）；
3. **时间轴**：该车的轨道高亮，其余轨道变淡。

### 6.2 选中车详情面板（右栏）

| 信息 | 来源字段 |
|---|---|
| 起点 → 终点（坐标 + 地图定位按钮） | `robots[].start/goal` |
| 到达时刻 / 是否到达 | `arrival` |
| 步数 / 等待步数 | `steps`、本地逐差计算（等待 = 前后同格） |
| 逐步明细表：`t · 位置 · 动作`（移动方向 ↑↓←→ / 等待 / 到达√ / 驻留◉） | `path[]` 派生 |
| 冻结前缀区间（动态模式） | `locked` + `path` 前缀 |
| "在时间轴上定位等待"：等待行可点击 → 回放跳至该 t 并暂停 | 派生 |

明细表行数 = 路径长（≤ 时域上限 1500），> 200 行时虚拟滚动（现有表格样式即可承载）。

### 6.3 大批量机器人（V07：不靠加颜色）

- **颜色策略**：固定 10 色 palette 循环复用 + 机器人**序号徽标**（圆内数字，LOD ≥14px 常显）；不引入第 11 种颜色。选中强调用形变（描边/标牌）而非新色；
- 列表工具：搜索框（匹配 id / 序号）、分组过滤（全部 / 在途 / 已到达 / 等待中 / 未完成编辑）、每车路径显隐开关（眼睛图标）、"仅显示已选"总开关；
- 图层面板提供"路径显示上限"滑杆（默认全部，> 40 车时可只画选中车的路径，避免 50 条线糊成一片）；
- 密集场景验收（32×32 × 50 车）时推荐操作路径：搜索或框选 → 专注模式 → 单轨回放。

## 7. 回放动画

### 7.1 时钟模型（纯 TS，可测）

```ts
class PlaybackClock {
  t: number; maxT: number; playing: boolean; speed: 0.25 | 0.5 | 1 | 2 | 4 | 8;
  // 基准步频 2 步/秒 × speed；rAF 累积时间换算步索引；
  // setState 仅在步索引变化时发生（≤16 次/秒 @8×）；时间轴读数走 DOM ref 直写，0 setState。
}
```

- 控件：⏮ 重播 · ◀ 单步后退 · ▶/⏸ 播放暂停 · ⏭ 单步前进 · 拖动 scrub · 速度 0.25×–8×；键盘：空格播放/暂停，←/→ 单步，Home/End 首末步；
- 回放结束自动暂停（不循环；循环留给"重播"键，避免误导为持续运动）。

### 7.2 机器人状态语义（4 态，图例常显于地图左下角）

| 状态 | 判定（由 `path[]` 派生） | 视觉 |
|---|---|---|
| 移动 | `path[t] ≠ path[t-1]` | 实心圆 + 运动方向楔形 |
| 等待 | 已出发未到达且 `path[t] = path[t-1]` | 空心圆 + 内部 ⏸ 点 |
| 到达 | `t = arrival`（一次性） | 实心圆 + ✓ 环（该步之后转驻留） |
| 驻留目标 | `t > arrival` | 实心圆 + 外圈光晕（stay-at-target 语义的可见化） |

路径进度：已执行段实线加粗、未来段虚线变细；机器人带 2 格尾迹渐隐。
**明确不做**：步内位置插值、速度曲线、加减速——离散同步模型下这些属于失真呈现（总则 4）。

### 7.3 时间轴（Canvas 自绘，非 DOM）

- 结构：上方统一步刻度轴（每 5 步主刻度）+ 每车一条水平轨道（y = 车序，x = 步）；
- 轨道分色：移动段 = 车色，等待段 = 灰色，驻留段 = 车色 20% 透明；动态模式下事件以 ⚡ 标记画在对应 `at` 时刻；
- 交互：点击/拖动 scrub（整块时间轴可拖）；点击某车轨道 = 选中该车（与地图/列表联动）；轨道可折叠（> 20 车时默认折叠为"仅选中车 + 全局占用热条"）；
- 冲突定位（§8）：violation 点击后时间轴在该 `at_time` 画红色脉冲游标；
- 实现约束：Canvas 绘制，1500 步 × 120 车上限内单次重绘 < 4ms（预热期实测写入验收报告）。

## 8. 冲突与算法解释

### 8.1 状态徽章语义（可展开"[?] 这是什么意思"）

| 徽章 | 通俗解释（展开文案，口径与 MODEL-MATH 一致） |
|---|---|
| OPTIMAL | 已证明：不存在更优（下界追平解值；`w>1` 时也必须界证明成立） |
| FEASIBLE | 有界次优解：给出下界与差距（如 +8.7%） |
| INFEASIBLE | 在**声明时域内**证明无可行解（`horizon: auto` 不享此结论） |
| UNKNOWN | 预算 / 展开上限耗尽：如实返回，不硬撑出错解；展示已找到的最好信息 |
| INVALID_INPUT / UNSUPPORTED / CANCELLED | 逐条 errors 原文 + 面向用户的解释 |

指标带常显：SOC · Makespan · 求解耗时 · 首解耗时 · 下界与差距 · 路径验证 ✓/✗（独立复核）· 等待步合计 · 引擎版本（可追溯到运行指纹）。

### 8.2 验证器面板（右栏"冲突与核验"组）

- **checks 列表**：verify 报告逐项 `name + ✓/✗`（如顶点冲突、边交换、目标占用、前缀一致性…）；
- **violations 列表**：`code · 涉及机器人 · at_time · cell · message`；每项可点击 → 地图红色脉冲定位该格 + 时间轴跳至该时刻并暂停——满足 SRS §5.5 "显示问题发生的位置和时刻"；
- 正常求解结果 violations 为空（引擎解已过验证器），面板显示"✓ 7 项检查全部通过（独立验证器）"。

### 8.3 冲突演示（教学负例，真实验证器）

入口：场景库"M11 篡改样例"卡片，或高级模式"验证任意方案"（粘贴/导入方案 JSON → `mapf_verify`）。

- 预置演示链：载入 m02 场景 + 导入 m11 风格的篡改方案 → 验证器返回 `E-CONFLICT-VERTEX / E-CONFLICT-EDGE / E-GOAL-OCCUPY` 等 → 地图与时间轴逐条定位——用户**亲眼看到验证器抓住了什么**，而不是看一段预制动画；
- 三类冲突的教学卡片（顶点 / 对向边交换 / 目标占用）内嵌说明文案 + 一键加载对应 mock（M02 / M03 / M04 / M06）。

### 8.4 搜索过程 vs 最终方案（SRS §5.5 红线）

`solution.search` 块（展开节点数、冲突计数等）只出现在**折叠的"搜索统计"**里，以数字表格呈现；**任何搜索期候选冲突都不会被画到地图或时间轴上**。地图/时间轴上的冲突标记只有一个来源：独立验证器的 `violations`。此规则写入 M1 代码评审 checklist。

## 9. 动态事件与重规划（V08）

### 9.1 进入条件与向导流程

前置：存在 `verified = true` 的成功解（回放模式）。工具浮条出现"⚡ 注入动态事件"：

```
① 拖动时间轴到 T（或播放中暂停）→ 点"⚡ 在 t=T 注入事件"
② 选择事件类型：加障碍 / 移除障碍 / 修改目标 / 作废路径
③ 地图上点选目标格（加/移障碍）或机器人+新终点（改目标）；
   事件生效时刻 at 默认 = T，可上调（未来生效，画在时间轴 T 之后）
④ 面板显示"将提交的 dynamic 块"预览（高级用户可核对的 JSON）+ 冻结窗参数
   frozen_steps（默认 1，0–4 可调）→【重新规划】
⑤ 真实调用 WASM mapf_solve（问题 = 基础场景 + dynamic 块）→ 新方案
```

### 9.2 UI 构造的契约块（严格按 `mapf-problem/1.0` `dynamic` 字段）

| 向导输入 | 契约输出 |
|---|---|
| 当前时间 T、当前方案路径 | `dynamic.snapshot { time: T, frozen_steps: k, paths: <当前方案逐车 path> }` |
| 加障碍（格 c，生效 at） | `events += { type: 'obstacle_add', cell: c, at, until: null }` |
| 移除障碍（格 c，生效 at） | `events += { type: 'obstacle_remove', cell: c, at, until: null }` |
| 改目标（车 r → g） | `events += { type: 'goal_change', robot: r, goal: g, at }` |
| 作废路径（车 r） | `events += { type: 'path_invalid', robots: [r], at }` |

连续多次事件 = 链式快照：每次重规划后的新方案自动成为下一轮 `prior_paths`（UI 维护，用户无需手写）。

### 9.3 提交前预检（引擎语义的 UI 前置，减少无效往返）

| 预检 | 依据（引擎会拒绝的真实语义） |
|---|---|
| 障碍生效时刻落在冻结窗 `[T, T+k]` 且某车冻结前缀此刻占用该格 | "承诺时段内出现新障碍 = 承诺不可维持"（`E-SNAP-*` 家族）——UI 直接说"AGV-3 已承诺在 t=T+1 经过此格，请把生效时刻后移或缩短冻结窗" |
| 新目标与其他车有效目标重复 | `E-ROBOT-DUP-GOAL`（goal_change 语义） |
| 事件总数 > 32 | wasm-light 能力 |
| at < T | `E-EVENT-TIME` |
| 基础场景本身仍有 error 级预检项 | 先修场景 |

引擎仍可能拒绝（预检不穷尽）：被拒时 `errors[]` 原文 + 解释文案照登，**不伪造成功**（总则 9）。

### 9.4 结果呈现（前后对比）

- **路径叠加**：旧路径 = 灰虚线；冻结前缀 = 实线 + 🔒 徽标（不可变承诺）；新增/改变段 = 车色高亮并加粗；
- **指标区**（引擎 `dynamic` 块原样呈现）：`replan_ms · affected_agents · path_change_steps · frozen_prefix_covered · forced_agents` + 事件回显列表（type/cell/goal/at）；
- **时间轴**：⚡ 事件标记；冻结窗底色条；新旧方案轨道上下相邻对比（旧轨半透明）；
- 撤销事件：向导第 ④ 步之前可任意修改事件列表；提交后若想回退，用"运行历史"回到上一运行（§10）。

## 11. 性能设计

### 11.1 渲染与 React 解耦（SRS §5.7 硬要求）

```
React 组件树（语义状态：场景/选择/工具/图层/回放状态）
   │ 仅语义变化时 setState
   ▼
MapRenderer（非 React 类，持有 4 层 canvas + rAF 主循环）
   ├─ L0 基底：场景或相机变化 → 重绘离屏缓存
   ├─ L1/L2：回放步或选择变化 → 增量重绘（culling）
   └─ L3：指针事件 → rAF 节流重绘
PlaybackClock（纯 TS）→ 步索引变化才通知 React
```

- 回放期间 React 更新率 = 步频（≤ 16 次/秒 @ 8×），且更新范围仅为时间轴读数等小组件（组件隔离，机器人列表不随每步重渲）；
- 播放中列表/图例等 DOM 读数（t = x/y）通过 ref 直写 `textContent`，**零 setState**；
- 求解期间（Worker 同步计算）：地图照常缩放/平移/回放旧解——"渲染与求解解耦"的直观验收点（取消 = terminate + 重建，现有语义）。

### 11.2 帧预算（验收目标）

| 验收场景（SRS §5.7） | 数据来源 | 交互目标（缩放/平移/scrub/选择） | 回放目标 |
|---|---|---|---|
| A：16×16 · 20 车 | `empty-16-16` + 自建/scen 取 20 对起终 | < 8 ms/帧 | 60 fps 稳定 |
| B：32×32 · 50 车 | `room-32-32-4` + scen 前 50 对 | < 16 ms/帧 | ≥ 30 fps（默认步频下远超） |
| C：大图密集 | `warehouse-10-20-10-2-1`（161×63）+ 24–48 车 | < 16 ms/帧（依赖 culling + L0 缓存） | 同 B |

注：这些场景验证**可视化交互**性能，不承诺对应规模问题在固定预算内求解成功（SRS §5.7 原文口径）。

### 11.3 关键技术要点

- 位置矩阵预计算：解到达后一次生成 `Float32Array[(maxT+1) × robots × 2]`，回放零路径遍历；
- L0 离屏缓存尺寸上限 4096px（超出自动降 dpr → 仍超则分块缓存）；
- 路径折线：同色车合并 path 绘制批次；50 车 × ≤1500 步的最坏折线用 culling 只画可视段；
- 时间轴同规格 Canvas 化（§7.3）；
- 内存：场景/运行均为 KB–百 KB 级；运行历史上限 20 条；无泄漏点（渲染器随组件卸载销毁，rAF 取消）。

### 11.4 性能取证

开发角标（`import.meta.env.DEV` 或 `?perf=1` 才显示）：实时 FPS / 上一帧 ms / p95；一键导出 `perf-log.json`（含场景指纹、引擎版本、帧样本）——V06/V07 验收时附在验收记录中，满足"真实性能报告"要求。

### 13.1 零改动声明（M1 验收的检查项）

### 13.2 场景文档 → 契约逐字段映射

| 编辑器概念 | 契约字段 | 备注 |
|---|---|---|
| 障碍网格 | `map.cells: string[]`（`.`/`#`） | 与 14 个 mock 同构，diff 友好；不使用 `map.blocked` |

| 时域 | `time_model.horizon`（默认 `auto`，高级可输具体值 1–1500） | `auto` 时不显示 INFEASIBLE 结论（引擎语义如实透传） |
| 优化目标 | `objective.kind` = `soc` / `makespan` | |
| 求解参数 | `solver.{planner, time_limit_ms, seed, suboptimality_factor}` | 范围受 schema 与能力双重约束 |

### 13.3 导入 / 导出兼容性（V10）

- **导出即契约**：导出文件可被 `mapf solve`、`check_contracts.py` 与现有 CI 全链路直接消费；
- **导入兼容**：接受引擎产出的任意 `mapf-problem/1.0`（含 `map.width/height + blocked` 表达、`benchmark` 块、`dynamic` 块）——未知/不消费的合法字段（如 `benchmark`）**原样保留**在场景文档旁路（`SceneDoc.extra`，导出时回写），不丢弃用户数据；
- **回归测试**：14 个 mock 做"载入 → 不编辑 → 导出 → 与源文件语义等价（规范化 JSON 深比较）"的 roundtrip 测试（§14.2）。

### 13.4 能力驱动 UI

机器人上限、格数、时域、预算、事件数上限全部来自握手到的 `mapf-capabilities/1.0`（失败时回退到文档值并标注"未验证档位"）。UI 不硬编码限额，避免引擎升级后界面说谎。

### 13.5 预检与引擎的关系（单一真相原则）

- 预检 = 编辑体验优化（提前挡住引擎解析期就会拒绝的结构错误），**永远以引擎错误码原文为最终呈现**；
- 前端**不做**解的合法性判断：路径是否冲突、SOC 是否正确，只看独立验证器输出（与 Lab README §5 约定一致）。

### 17.1 体验脚本 A：V03 双车交叉（M1 验收时按此走查）

1. 打开 MAPF Lab（未求解，地图已在场）→ 选"空白 8×8"模板；
