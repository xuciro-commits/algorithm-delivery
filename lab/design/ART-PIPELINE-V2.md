## 一、目标与三条不变式

阶段一的目标是把"已上传的工业三维模型"变成可实时交互的**工业科技插画风格数字实验室**，
而不是做照片级工业仿真，也不是重做模型。

实现遵守三条不变式：

1. **几何只来自上传资产**：`lab/design/assets/**` 是只读来源，运行时通过
   `lab/scripts/sync-assets.mjs` 复制到 `lab/public/models/**`（可重建、不进版本库）。
   艺术化只替换材质、调整可见性、分层透明与灯光，**不修改顶点、不重建网格、不替换设备**。
2. **三模式共用同一份几何与同一份算法数据**：模式 A / B / C 只是视觉配置（材质、透明、灯光、
   雾、曝光、发光强度）的切换，不是三套模型；算法叠加层来自同一份引擎输出。
3. **算法可视化必须来自真实引擎输出**：三维实验室里的路径、节点、状态光、事件标记全部由
   AGV / MAPF / APS 引擎的真实解投影而来；没有结果时显示"未运行"空叠加层，不用装饰动画充数。

## 三、三种视觉模式（模式 A / 模式 B / 模式 C）

| 维度 | 模式 A 工业原貌 | 模式 B 工业科技艺术化（本轮主目标） | 模式 C 算法观察 |
| --- | --- | --- | --- |
| 材质 | **原始 glTF 材质**（`forceOriginals`，无替换） | 冷色工业材质 + 分层金属（角色外观表） | 同 B，但次要对象进入弱化变体 |
| 背景 / 雾 | `GRAPHITE.deep`，无雾 | `GRAPHITE.base`，雾 18→74 m | `GRAPHITE.void`，雾 14→62 m |
| 曝光 / 色调映射 | 1.12 / ACES | 1.06 / ACES | 1.00 / ACES |
| 建筑层透明强度 | 0（结构外壳不透明） | 1.0 | 1.0 |
| 设备外壳透明强度 | 0 | 1.0（仅命中策略的外壳/玻璃） | 0.85 |
| 弱化系数 `deEmphasis` | 1（不弱化） | 1（不弱化） | 0.45（次要建筑/设备） |
| 主光 / 补光 / 轮廓光 | 2.15 / 0.72 / 0（1024 阴影） | 2.45 / 0.78 / 1.5（2048 阴影） | 2.10 / 0.66 / 1.9（1024 阴影） |
| 地坪反射 | 0.24 | 0.42 | 0.30 |
| 发光强度 `glowScale` | 1 | 1 | 1.4（路线/节点更亮） |

模式 A 的用途是**结构核对**：它保留原始材质与配色，用来确认"艺术化没有改变几何与零件划分"。
模式 B 是交付主形态；模式 C 在 B 的基础上弱化次要建筑与设备，突出算法路径、关键节点与任务状态。

三种模式通过应用壳顶部的**全局视觉模式条**（`src/components/hud/ArtModeBar.tsx`）切换：
同一个开关同时作用于三维实验室与既有的 APS / MAPF / AGV 沙盘（它们读同一个 `useArtStore`），
切到模式 A 时既有沙盘回落到改造前的灯光与原始材质，行为与改造前一致。

## 四、透明策略：选择性透明，不是整场透明

透明只有一个入口：`src/art/roles.ts` + `part-roles.json` 的 `transparencyPolicy`：

| 规则 | 命中对象 | 作用域 | 基准 α | 实际效果 |
| --- | --- | --- | --- | --- |
| `group: roof` | 屋面、天窗 | 建筑层 | 0.10 | "透明厂房"下滑透或隐藏 |
| `group: structure` | 柱、屋架、墙板、楼层板 | 建筑层 | 0.14 | 保留空间关系但不遮挡视线 |
| `group: floor` | 地坪构件 | 建筑层 | 0 | 直接隐藏（运行时另有程序化地坪） |
| `role: glazing` | 玻璃门窗、观察窗 | 设备层 | 0.26 | 冰蓝玻璃，depthWrite 关闭 |
| `role: shell` | 设备外壳、防护罩 | 设备层 | 0.42 | 银白/冰蓝半透明外壳 |
| `role: floor` | 设备自带地面 | 设备层 | 0 | 隐藏 |

**永不透明**：`frame`、`graphite`、`machined`、`drive`、`robot`、`conveyor`、`cargo`、`vessel`。
也就是说：外壳半透明，**内部机械结构始终是不透明金属**，这正是"能看清内部机构"的前提。

三道工程防线（避免大面积透明件的穿透噪点）：

1. 透明件统一 `renderOrder = 12`，排在不透明几何之后绘制；
2. 透明件 `depthWrite = false`，避免互相遮挡造成的"黑洞"；
3. 有效 α ≤ 0.02 时直接 `visible = false`（例如被隐藏的屋面），不再参与填充与排序。

透明强度可实时调整：面板右栏的"结构透明强度 / 外壳透明强度"滑杆分别缩放到建筑层与设备层，
"高质量玻璃"开关在 `MeshStandardMaterial` 与 `MeshPhysicalMaterial(transmission)` 之间切换。

## 五、材质与角色体系（不抹平设备差异）

- 角色由**材质名 + 节点名 + 几何启发式**判定（`classifyMesh`），共 17 类语义角色：
  外壳 / 框架 / 石墨 / 加工面 / 玻璃 / 橡胶 / 警示 / 驱动 / 机器人 / 输送 / 载货 / 容器 /
  机加工件 / 控制 / 灯光 / 电缆 / 未知。
- 每个角色在每种模式下有独立外观（颜色、粗糙度、金属度、清漆、自发光、双面、
  透明度），**不是统一的蓝色涂层**：主体是冷灰/银白，重要结构是深石墨，半透明外壳是冰蓝/青，
  状态与警示用克制的琥珀橙。
- 材质库按 `模式:角色:变体:α(0.01 量化):玻璃类型` 复用实例，避免每台设备重复建材质；
  但**同一角色在不同设备上仍保留真实差异**（几何、部件组、透明命中范围不同），
  面板上每种设备的角色分布与透明件计数都是实测结果。
- 一键还原：每个 mesh 的原始材质、可见性、renderOrder、阴影开关都会在首次修改前记录，
  模式 A / "原始材质"视图 / 组件卸载时按记录还原，`useGLTF` 缓存不被污染。

## 六、灯光、相机与性能

- **环境光**：`warehouse-studio.hdr`（本地）经 PMREM 生成环境贴图，提供金属与玻璃的反射来源；
  `ArtSceneEnvironment` 按模式调整强度、雾与背景，让发光线条与背景形成主次。
- **主光**：带阴影的方向光，模式 B 用 2048 阴影贴图 + 柔和 PCF，阴影范围按场景跨度自动推导；
  反向冷色补光提供轮廓分离；轮廓光只作用于边缘，不参与整体照明。
- **工业局部光**：按柱距布置的厂房灯具（真实构件 `high-bay-light-fitting`）+ 受控点光，
  用于生产区可见性，不是霓虹装饰。
- **接触阴影**：设备与工位底部渐隐暗面（假 AO，无阴影贴图开销），提升"落地感"；
  可在面板关闭。
- **相机**：沙盘用透视相机（模式 C 视场角更大）+ 阻尼轨道控制，5 个预设机位由厂房真实尺寸推导；
  英雄实验台另有 5 个按设备真实包围盒推导的机位（3/4、正面、侧面、俯视、内部）。
- **性能红线**（`node lab/scripts/audit-perf.mjs` 持续断言）：
  不做后处理泛光（发光 = 自发光材质 + 细线 + 低透明外晕）、`dpr ≤ 2`、
  `frameloop` 按 `active` 在 `always / demand` 间切换、`useFrame` 内不新建对象。
  离散步回放（默认 220 ms/步）才开启连续渲染；静止画面通过
  `RenderOnChange`（`src/art/RenderOnChange.tsx`）在模式/视图/数据变化后补帧，静止时零 GPU 负载。

## 八、算法空间语汇（全部来自真实引擎输出）

| 算法 | 真实来源字段 | 空间语汇 |
| --- | --- | --- |
| AGV 调度 | `solution.plan.vehicles[].timeline`、`plan.tasks[].{pickup_dock,dropoff_dock,*_arrival,*_done,flow_time,lateness,status}`、`missions[].{phase,from,to,dock}` | 已执行/计划轨迹（虚线 + 光流相位）、任务取送点、相位状态光、`lateness > 0` 超期事件标记 |
| MAPF 路径 | `solution.robots[].path`、`arrival/steps/soc/makespan` | 每机器人独立配色轨迹、目标位置投影、到达状态环 |
| APS 排程 | `RunRecord.solution.operations[].{start_at,end_at,machine_id,order_id}`、`verify.violations` | 工位状态光（按机型颜色）、同订单工序流转线、核验违规标记、按引擎时间轴的离散步回放 |

坐标换算只有一处：`lab/src/modules/art-lab/layout.ts` 的格阵映射
（`createGridMapping` → `cellToWorld`，等比居中到 `ALGO_ZONE`）。算法侧只提供格坐标，不做视觉缩放。

面板会显示叠加层来源（哪个引擎、哪个样例、什么状态）与映射说明；引擎未就绪或清单缺失时
给出可操作提示（例如"请先运行 `node lab/scripts/sync-agv.mjs`"），**不显示伪造结果**。
